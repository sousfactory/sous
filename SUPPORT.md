# Support

sous is maintained by one person and used in the open. Everything below is
public, searchable and answered as time allows, usually within a few days.

| You have | Go to |
| --- | --- |
| A question about a step, a flow or a run | [Discussions, Q&A](https://github.com/sousfactory/sous/discussions/categories/q-a) |
| A flow or step worth showing | [Discussions, Show and tell](https://github.com/sousfactory/sous/discussions/categories/show-and-tell) |
| An idea that is not yet concrete | [Discussions, Ideas](https://github.com/sousfactory/sous/discussions/categories/ideas) |
| A bug, or a concrete feature request | [Issues](https://github.com/sousfactory/sous/issues/new/choose) |
| A security problem | [A private advisory](https://github.com/sousfactory/sous/security/advisories/new), see [SECURITY.md](SECURITY.md) |

Before asking, check [the manual](docs/manual.md); its
[troubleshooting chapter](docs/manual.md#22-troubleshooting) covers the
common stops. A bug report wants the `sous-factory` version and the output
of `./sous status <issue>`; for a blocked run, add the eval log of the
blocked step from `.sous/logs/<issue>/`. The issue form asks for exactly
that.

Teams that want help adopting sous, or a flow built for their stack, can
talk to [Inauditech](https://www.inauditech.com), which sponsors the
project. That is a separate conversation and does not move an issue up the
queue.
